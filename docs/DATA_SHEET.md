# Data sheet: Safe-Send synthetic dataset

## Motivation
No real mobile-wallet transfers were available. The data is generated to test a pre-confirmation scam-risk method, including look-alike legitimate behaviour so the classes overlap.

## Composition
- 75,682 transfers and 3,296 accounts over 60 days (1 July to 29 August 2026). Scam transfers: 919 (1.2%).
- Account roles: 3,192 normal, 64 mule, 40 scammer.
- Scam patterns: mule fan-in (504), amount splitting (205), return scam (120, with 120 setup transfers), account takeover (90). Mule cash-outs (184) are labelled 0 and used for features.
- Legitimate look-alikes: welcome money to new wallets (712), large transfers (613), new-merchant bursts (320), legitimate fan-in (351), genuine returns (150), large transfers from a new device (60).
- Columns starting with `gt_` are ground truth for evaluation only and are never features.

## Collection process
Generated by `src/data_gen/generate.py` with a fixed seed (42). Harder variants (slower and smaller rings, older mule accounts, SIM-swap takeovers, partial returns) were added after a first run was unrealistically perfect.

## Preprocessing
`src/features/build.py` builds 32 features from past data only. A test shows that recomputing with only earlier rows gives identical values (no leakage).

## Uses and limits
Suitable for developing and testing the method. Not suitable for estimating real accuracy, loss prevented or fairness in production. Distributions, amounts and fraud rates are assumptions.

## Privacy
No real people or accounts. Identifiers are synthetic.

## Maintenance
Regenerate with `python -m src.data_gen.generate --out data --seed 42`. CSV files are git-ignored; `data/summary.json` is committed.
